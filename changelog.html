v2.1.2.4-Beta

Beta

修掉 v2.1.2.3-Beta 反馈的两处缺陷：默认收藏组名称乱码、比例填完又被改回去；比例改为直接输入 1–100，并新增可编辑的指令/ID 预览框。

修复

默认收藏组名称乱码

配置文件读写用的是平台默认编码，中文 Windows 上是 GBK。一旦配置曾在 UTF-8 环境写过（例如用 Java 21 的启动器跑过一次），读回来就是「榛樿鏀惰棌」这类乱码，还会被原样存回文件。

现在读写统一 UTF-8，读取失败自动退回 GBK 兼容旧文件，并对已经写坏的组名做一次还原。

比例填完被改回原值

旧实现把输入值当成「占总量的百分比」，再按其他方块的权重反推一次原始权重，反推后一取整就和输入值对不上，看起来就是刚填完又被改回去。

现在比例是 1–100 的相对权重：输入什么就存什么、指令里就是什么，不再二次换算，也不要求各项加起来等于 100。

比例拖不动

可拖动的细条只有 26 像素宽，百分比数字画在它右边 40 像素处，玩家基本都拖在数字上；Fabric 与 1.19.2 侧还把百分比直接当成原始权重写入。

已去掉拖动，改为点击比例方框直接输入：认「50」也认「50%」，清空即回到 100。

新增

指令 / ID 预览框

界面底部实时显示当前会输出的完整内容，可以直接在框里改；点复制时以框里的内容为准。切换方块、改比例、改方块状态后会重新生成预览。

变更

比例全为 100 时不输出百分比

所有方块都是默认比例时直接输出 //set stone,dirt，交给 WorldEdit 等概率随机；只要有方块改过比例，就把各自的数值原样带上。

输出前自动校验

方块 ID、比例数字、方块状态写法、以及「比例全带或全不带」都会检查；不通过时预览框下方红字提示「当前指令格式/方块ID不正确」，并禁止复制与输出，动作栏同时指出是哪一段不对。

状态

四个版本已构建完成，等 QQ 群分发；现在就要用的话，建议先停在 v2.1.2.2-Beta。

模组图标显示为破图

现已将 4 个版本共 6 份图标统一转为真正的 PNG（512×512，RGBA），配置中的 icon 路径不变。

v2.1.2.2-Beta

Beta

修复方块权重无法精确控制的问题：权重改为 WorldEdit 原生的相对权重语义，三个及以上方块也能准确设置 50% / 25% / 25% 这样的比例。

修复

方块权重无法精确控制

旧逻辑在设置某个方块后，会把剩余配额按其他方块当前值的比例重新分配。逐个输入目标值时，先前设置好的方块会被后续操作反复缩放，任何顺序都无法精确落在目标分布上。

典型场景：三个方块想设为 50% / 25% / 25%，结果总在漂移，怎么调都对不上。

改为相对权重语义

WorldEdit 的 50%stone,25%dirt,25%sand 本就不要求总和为 100，是相对值。现在输入的数值就是该方块的相对权重，各方块独立设置、互不干扰。

三个方块依次输入 50、25、25，即得到精确的 50% / 25% / 25%。

变更

界面权重显示

显示实际占比（该方块权重 ÷ 组内总权重），与生成指令的真实分布一致

权重输入范围

由 1–99 扩展为 1–9999，支持更悬殊的比例

拖拽滑条

仍按百分比位置操作，内部自动换算为相对权重

增删方块

不再触发全组权重重分配，其余方块保持原值

兼容性

全默认状态（未调整权重）生成的指令与旧版完全一致

组内任一方块有自定义权重时，全部方块都会带上 N% 前缀（WorldEdit 中无前缀方块的权重为 1，混用会产生错误比例）

验证

四版本（Forge / Fabric × 1.20.1 / 1.19.2）compileJava 与 clean build 全部 BUILD SUCCESSFUL

旧权重逻辑无残留，四份源码新增方法一致

v2.1.2-Release

Release

阶段 0「止血」的收官版本：完成默认键位调整与文档版本校正，补齐四版本统一构建，并新增一项 WorldEdit 联动能力。

修复

修复三个版本漏初始化收藏与历史记录

此前只有 Forge-1.20.1 在启动时完整初始化了 ConfigManager / FavoritesManager / HistoryManager，其余三个版本（Forge-1.19.2、Fabric-1.20.1、Fabric-1.19.2）只初始化了配置管理器。

由于两个管理器带有「首次访问时兜底初始化」的逻辑，该问题不会导致崩溃，但「默认收藏」分组不会在启动时写入配置文件，历史记录的初始状态也不可靠。

现四个版本已在启动时统一完成三项初始化。

变更

默认键位改为 G / H

打开方块 ID 管理界面为 G，复制手中方块 ID 为 H。

此前复制键默认绑在 C，该键在整合包中冲突概率较高，故调整。两个键均保留默认绑定，玩家仍可在「选项 → 控制 → 方块ID」中自行修改。

新增

检测到 WorldEdit 时直接执行指令

（1.20.1 版本）：生成 //set / //replace 指令后，若检测到环境已安装 WorldEdit，会直接把指令发送执行，省去手动打开聊天栏再粘贴的步骤。

指令始终会先写入剪贴板，因此即便自动发送失败仍可手动粘贴执行，不影响原有用法；未检测到 WorldEdit 时保持原行为：仅复制并提示需要手动执行。

1.19.2 未提供对等的指令发送接口（该版本聊天签名机制与 1.20.1 不同），因此保持「复制到剪贴板」的行为。

工程

补齐四版本统一构建

此前仅两个 Fabric 目录内带有 workflow 文件，但它们位于仓库子目录，GitHub Actions 不会执行（该服务只识别仓库根目录的 .github/workflows/）。

现已在仓库根目录建立统一的 build.yml，用矩阵任务一次性构建 Forge / Fabric × 1.20.1 / 1.19.2 四个版本并上传产物，同时移除子目录中不会生效的旧配置文件。

v2.1.1-Beta

Beta

无需新增功能的质量补丁，目标是让模组从「装不上」变成「装上就能用」；同时替换掉打包在制品中的 GPL 系拼音库，消除协议风险。

修复

WorldEdit 不再被判定为必需前置

此前模组虽在依赖清单中声明 WorldEdit 为 mandatory=true，但代码里从未调用过它的任何 API，只是把 //set / //replace 字符串写进剪贴板。

没装 WorldEdit 的玩家会直接被判定依赖缺失、游戏读不到模组；崩溃日志中确实存在 requires worldedit 0 or above / Currently, worldedit is not installed。

现已改为可选依赖并增加运行时检测——未安装时功能完全不受影响，仅在提示语中说明指令需手动粘贴执行。

移除从未被引用的 Cloth Config 前置

构建脚本声明了 Cloth Config、说明文档也把它列为必需前置，但源码中零引用。现已彻底移除，减少一项无谓的安装门槛。

修正 Forge 1.19.2 的模组元数据

该版本的 mods.toml 存在三处错误——loaderVersion 键名拼写错误且取值写成了模组自身版本、Forge 版本范围沿用了 1.20.1 的 [47,)、游戏版本范围写成了 [1.20.1]，会导致 1.19.2 的 Forge 包加载异常。

现已修正为 [43,) / [1.19.2]。

修正 1.19.2 版本文档描述

该版本说明文档此前错误地写着 Minecraft 1.20.1、Forge 47+、Fabric 0.15+，现已按实际支持的版本分别更正。

变更

替换内置拼音库，消除协议冲突

此前模组把 pinyin4j 直接打包进主 Jar，该库采用 GPL 系协议，与本项目「允许学习修改、禁止二次发布修改版本」的自有协议直接抵触。

现已替换为 Apache-2.0 协议的 TinyPinyin，并将无需使用的传递依赖一并排除。安装包体积平均减少约 190 KB（Forge 约 −197 KB，Fabric 约 −190 KB）。

中文拼音搜索行为保持兼容

新旧库对 ü 的记法不同——旧库把「绿」记作 lu，新库记作 lv。

为不让惯用 lu 的玩家搜不到方块，已同时生成两种写法的索引，输入 lvbaoshi 或 lubaoshi 都能搜到「绿宝石块」，其余方块名的搜索行为完全一致。

清理

删除空实现的 ClientEvents 事件订阅器（四个版本各一份，无任何实际行为）

移除构建脚本中随依赖删除而失效的第三方仓库配置

文档
